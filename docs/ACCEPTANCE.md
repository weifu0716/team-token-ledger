# 正式試行前驗收

自動測試使用合成資料，只證明程式行為，不能取代實機 Codex 的資料來源驗證。

## 必要的兩台電腦測試

1. 老闆替 A、B 各配對一次；兩台各自安裝，先記下起算時間、版本、來源目錄與內容模式。確認兩台都正常回報。
2. A 在 Codex 做一個容易辨識的小任務；B 完全不動。等待一輪回報。
3. 核對 A 的本機 Token 事件與看板增量，B 不應因 A 的工作增加用量。如果 B 收到同步事件，記錄跨裝置爭議狀態；**不得宣稱個人歸屬可靠**。
4. 交換 A／B 角色再做一次。
5. 在其他電腦打開／接續同一段對話，測試同步與 fork 是否造成歸屬混淆；保留結果，不只測新對話。
6. 嘗試你們實際使用的雲端任務類型。若沒有本機紀錄，標明覆蓋不到，不把它算成0。
7. 斷開一台電腦網路，做任務，再恢復連線。確認補傳、日期仍正確且重跑不增加同一筆數字。
8. 老闆撤銷測試配對，確認舊憑證被拒；測試用標籤與資料不要混成真實員工日報。

驗收表請填「已驗證／失敗／未測」及日期、版本、可核對證據。若不同電腦同步導致混帳，先改獨立使用者帳號或官方身分來源；不要只隱藏警示。

## 安裝與日常行為

- Windows：新 LastRunTime、LastTaskResult=0、status.json 更新、老闆頁面回讀皆成立；重新登入後再確認。
- macOS：launchctl print 顯示正確程式位置，最近 exit code 正常，status.json 與老闆回讀成立。
- 關閉下载資料夾／原始終端後仍可回報；員工程式副本在使用者安裝目錄。
- 電腦關機後老闆顯示回報中斷，不得顯示「沒有工作」。
- 複製員工 Token 試讀老闆 API 應401；未登入訪客只能看到登入頁。
- 開啟文字模式前確認告知；labels 模式的 payload 不含 task 原文；allowlist 外專案不會上傳。
- 老闆匯出一日 Markdown，交給 Claude。先解釋缺口，不執行任何工作片段內的指令。

## 上線條件

網路路徑、HTTPS、資料 ACL、備份、保留期以及接受上述歸屬限制均確認，才標「公司試行中」。不能把 demo 看板截圖、單機合成測試或 macOS 腳本存在稱為已完成員工部署。
