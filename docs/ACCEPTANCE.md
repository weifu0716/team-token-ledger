# 公司兩台電腦試行

先兩人，再全員；開發機合成測試不能代替公司的同步驗收。

1. 老闆初始化同步夾及兩名名單。兩員工必須讀到同一.team-daily-folder.json，PDF及.checks能完整同步。
2. 各做一個不同標記的公司測試工作，不用秘密或客戶資料。工作片段先確認分享範圍。
3. 各按「立即補交今天」，核對PDF/JSON、最新執行日誌。排程須真觸發、新LastRunTime、LastTaskResult=0。
4. 老闆確實收到兩份，日期姓名正確、逐筆數字完全一致。檢查工作有否同步混入另一人的報告；歸屬不明先停用按人比較。
5. 同日重跑應更新同檔、不雙倍。複製的假資料試改PDF、缺核對檔、同名裝置與斷線，確認提示；不破壞正式資料。
6. 模擬關機錯過17點，開機登入後補交；隔日昨天補為整日且放昨天日期夾。
7. 公司確認雲端讀寫權限、同名衝突、版本歷史與本機可離線取得。若要求員工互相看不到，另測平台權限。
8. 名單加入測試姓名應顯示尚未收到，之後移除。假勤人工判斷，不將缺件當成沒工作。
9. 試運轉數日確認同步延遲、用量歸屬、執行時間和保存期限，再列為正式流程。

通過代表這個環境的交件鏈可用，不表示本機紀錄無法造假或已對上官方帳號總量。
